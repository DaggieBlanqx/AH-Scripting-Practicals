## Executive summary

The access log for `shop.meridianretail.com` covers 2499 requests from 157 client IPs; 1026 rows (41%)
carry attack indicators, from 7 distinct addresses:

- Automated tooling (`acunetixscanner sqlmap/1.7.2#stable`) scanned the application over 137 requests. 980 requests carried injection payloads across 2 endpoint/parameter pairs. 
- 840 blind boolean probes over 1.8 h pulled column values out one character at a time. UNION queries paged out 5 tables (admin_sessions, employee_payroll_view, gift_cards, saved_payment_methods, users).

The attacker asked the database yes/no questions - "is character N of the admin
password hash greater than 55?", "does it equal 0x62?" - and inferred the answer
from the response shape rather than from any error. Roughly 840 probes decoded a
credential column a character at a time. This is the quietest stage in the log:
every request returned 200 with a plausible response size.

## 5. UNION-based dumps

83 UNION requests; schema objects probed: `information_schema.columns information_schema.tables`; paging: 40 dump pages of 50 rows (offsets 0..350).

| Table | Dump requests | Columns exfiltrated |
|---|---:|---|
| `admin_sessions` | 8 | `session_token,user_id,expires_at` |
| `employee_payroll_view` | 8 | `employee_name,salary,bank_account` |
| `gift_cards` | 8 | `card_code,balance,issued_to_email` |
| `saved_payment_methods` | 8 | `card_number,card_expiry,cvv_hash` |
| `users` | 8 | `username,password,email` |

The attacker first sent `UNION SELECT NULL` probes to count columns, then replaced
each `NULL` with a column of interest and paged through the table 50 rows at a time.
Column-count probing is the signature to alert on: a normal customer never sends
`UNION SELECT` anywhere near a product page.

## 12. Root cause and remediation

**Root cause.** User input reached SQL string concatenation on two surfaces: the read
path (`/product/detail?id=` and `/search?q=`) and the authentication path
(`/account/login`). Because the query text changed with attacker input, one injection
point cascaded into schema enumeration, credential theft and a full login bypass
(OWASP Top 10 A03:2021 - Injection). The exported backups and payroll data show the
database account also had far more read access than a storefront needs.

| Priority | Action |
|---|---|
| P0 | Revoke session `sess_9f2c1a`, rotate all admin credentials, force resets on the 6 compromised customer accounts. |
| P0 | Treat the 5 dumped tables as breached: regulator and card-network notification, customer notice, forensic image of the database host. |
| P1 | Replace every string-built query with parameterized statements (or an ORM that enforces them) on `/product/detail`, `/search` and `/account/login`. |
| P1 | Give the web application a least-privilege database account: no schema access, no `UNION`-readable credential or payroll tables, no backup privileges. |
| P1 | Add MFA and rate limiting to login plus breached-password detection; alert on login bursts from one /24. |
| P2 | Extend WAF rules to UNION, blind inference and auth-bypass payloads; alert on any request whose query string contains SQL keywords. |
| P2 | Block the attacker IPs and alert on `sqlmap`/`Acunetix` user agents, `%27` in query strings and sequential `product/detail?id=` enumeration. |
| P2 | Require re-authentication for `/admin/*` and treat bulk export/backup endpoints as high-risk actions needing approval and logging. |
